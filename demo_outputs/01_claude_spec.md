PulseTask: Architecture Spec 1. Architectural Overview Stack: Vanilla JS (ES modules), a single index.html, CSS variables, and localStorage (or IndexedDB if the data may grow large). It has no backend and no build step, and it works offline once loaded. A service worker plus manifest can make it an installable PWA. Pattern: unidirectional data flow, Action → Reducer/Store → State → Render.  /pulsetask ├── index.html ├── styles.css ├── sw.js # optional: offline cache └── /src ├── main.js # bootstrap: load → subscribe → render ├── store.js # state container, dispatch, subscribe ├── actions.js # pure state transitions (the logic engine) ├── selectors.js # derived data: filtered/sorted cards ├── storage.js # persistence, migration, import/export ├── models.js # factories, constants, validators ├── dnd.js # drag & drop handlers └── /ui ├── header.js ├── filterBar.js ├── column.js ├── card.js └── cardModal.js Layers: Layer Responsibility Rule Model Schemas, factories, validation No DOM access Logic Pure functions (state, payload) → newState No side effects Store Holds state, notifies subscribers, triggers persistence Single source of truth UI Renders state, dispatches actions Never mutates state directly Storage Debounced save, schema migration, JSON I/O Isolated behind an interface Key decisions: Normalized state. Cards live in a map and columns hold cardIds, so moves are O(1) and no data is duplicated. Filters are UI state, not data. Filtering is derived in selectors and never mutates cards. Versioned schema (schemaVersion) enables safe migrations and import validation. Debounced autosave (~300 ms) on every state change. 2. State Management Functions All are pure functions in actions.js of the form (data, payload) → newData. Board createBoard(title) renameBoard(boardId, title) deleteBoard(boardId) setActiveBoard(boardId) Column addColumn(boardId, title) renameColumn(boardId, columnId, title) deleteColumn(boardId, columnId, moveCardsTo?) – either deletes the cards or relocates them reorderColumns(boardId, fromIndex, toIndex) setWipLimit(boardId, columnId, limit | null) Card addCard(boardId, columnId, { title, description, priority, labels, dueDate }) updateCard(boardId, cardId, patch) – refreshes updatedAt deleteCard(boardId, cardId) duplicateCard(boardId, cardId) moveCard(boardId, cardId, toColumnId, toIndex) – covers both reorder within a column and move across columns setPriority(boardId, cardId, priority) UI / Filters (store.setUI) setSearchQuery(q) togglePriorityFilter(priority) toggleLabelFilter(label) setDueFilter(value) setSort(sortBy) clearFilters() Selectors (selectors.js) getActiveBoard(state) getVisibleCards(board, columnId, filters, sortBy) – applies search, priority, label and due filters, then sorts getAllLabels(board) getColumnStats(board, columnId) – total, visible, overdue count, WIP exceeded isOverdue(card) Persistence / IO (storage.js) loadData() – read, parse, migrate, fall back to the seed saveData(data) – debounced write to localStorage migrate(data) – step through schemaVersion exportJSON(data, scope: "board" | "all") – returns a Blob and triggers a download as pulsetask-YYYY-MM-DD.json validateImport(json) – checks schema, ID integrity and orphaned cards, and returns { ok, errors, data } importJSON(file, mode: "replace" | "merge") – on merge, re-keys colliding IDs Store core getState() dispatch(actionFn, payload) – runs the action, then notifies subscribers, then schedules the save subscribe(listener) undo() / redo() – optional, using a snapshot stack of the last ~50 states 4. Board switcher dropdown, with new, rename and delete options. Export (downloads JSON) and Import (file picker, then a replace/merge prompt). Theme toggle (light/dark via CSS variables) and an offline/saved status indicator. Search / Filter bar (sticky below the header) Search input, debounced ~150 ms, matching title, description and labels. Priority chips as multi-select toggles, color-coded. Label multi-select, due-date filter and sort dropdown. An active-filter count badge, a “Clear filters” button, and a “Showing X of Y cards” readout. Columns Horizontally scrolling flex container, with each column a fixed width of about 300 px. Column header: inline-editable title, card count (shown as n/limit when a WIP limit is set), and a kebab menu with rename, set WIP limit and delete. WIP limit exceeded: header turns warning-colored. Vertically scrollable card list that acts as a drop zone, with an empty-state placeholder. Footer with an “+ Add card” inline composer (title field, Enter to save, Esc to cancel). A trailing “+ Add column” ghost column. Task card Priority indicator: colored left border plus a badge (Urgent = red, High = orange, Medium = blue, Low = gray). Color is never the only signal, so the badge always has a text label or icon. Title, at most 2 lines. Description snippet, 1–2 lines, truncated. Label chips. Footer with due date (red when overdue, amber when due today), and a hover quick-actions menu for priority, duplicate and delete. Click opens the card modal with full edit fields: title, description, priority select, labels input, due date picker, and Save / Delete. Cards that don’t match the active filters are hidden, and the column count reflects that. Interaction & quality requirements Drag and drop via the HTML5 Drag and Drop API, with a visible drop indicator. Pointer-event fallback for touch. Keyboard support: / focuses search, N adds a card, Esc closes the modal. Cards are focusable, and arrow-key moves are a nice-to-have. Responsive: columns snap-scroll on mobile. Accessibility: ARIA roles (list, listitem), labeled controls, 4.5:1 contrast, and prefers-reduced-motion respected. Escape all user text on render (textContent, never raw innerHTML) to prevent XSS from imported JSON. Storage errors (quota exceeded, corrupted data) show a non-blocking toast. Failed imports never overwrite existing data. I can go further on any piece, such as the full store.js and actions.js implementation or a working single-file prototype.
